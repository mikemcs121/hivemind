        Getting started
        
            
          
              
        1. First run — get an agent connected. Hivemind runs agent command-line tools (Claude Code, OpenAI's Codex, Gemini, Grok) in its threads; it never talks to a model service itself, so at least one of them has to be installed on this machine. The first time you open Hivemind with no hives, a setup wizard appears: it shows every agent with a live status — ready, sign-in needed, or not installed — read from this machine, gives you the exact install command (with a ⧉ Copy button) for the one you pick, and re-checks by itself while you install it in another window. The last step makes your first hive and opens a thread on the agent you chose. Signing in happens in that thread, in the agent's own sign-in screen. You can reopen the wizard any time from ⚙ Settings → General → Agent setup, from the Set up an agent button on the welcome screen, or by saying “Hivemind, run setup”. On every later start Hivemind shows Loading your hives… until your saved hives are open, so the welcome screen and the wizard only ever appear when there really is nothing set up.
          2. 
              
        2. Click ＋ next to the logo to create a hive and point it at a project directory — pick an existing folder with Browse…, or use ⬇ Clone a project from GitHub… to sign in to GitHub and clone one of your repositories into a new folder first.
          3. 
              
        3. Press ＋ Thread to open a Claude thread — open as many as you like; they all share the hive's directory. Threads tile up to three across, then wrap onto a second row (the fourth thread stacks under the shortest column). Drag the bars between threads to resize them.
          4. 
              
        4. Use the
                 Explorer
                and
                 Source Control
                buttons to browse files and manage Git, the
                 Publish
                button to upload a website to your web host over FTP, and the
                 Prompt History
                button to see the prompts you've sent in this hive — click one to jump to that prompt in the conversation where it appears (the thread is focused and the message flashes briefly). Use the visible ➤ button to send it again to the focused thread. Hover an entry for 🎤 to re-speak that prompt in voice training (read it aloud and accept dictionary fixes for anything misheard), or 🗑 to remove it from the list.
          5. 
              
        5. While one of those panels is open the sidebar keeps the hive you're working on pinned at the top, so you can always see which project the panel is showing. Click that pinned row (marked ⌄) to drop down the full hive list and switch hives without closing the panel.
          6. 
              
        6. Drag the sidebar's right edge to make it (and the Explorer, Source Control, Publish, Prompt History and 🐝 Chat with Hivemind panels docked in it) wider or narrower. Double-click the edge to reset the width; it's remembered across restarts.
          7. 
              
        7. Hide the sidebar with the « button next to the Hivemind logo (or Ctrl+Shift+B) to give your threads the whole window. A » button appears at the left of the toolbar to bring it back — same shortcut, or say “Hivemind, show the sidebar”. Whether it's hidden is remembered across restarts, and opening any docked panel (Explorer, Source Control, Prompt History, 🐝 Chat) brings the sidebar back automatically.
          8. 
            
        
          
        

          
        
            
        Threads
        
            
          
              
        • Voice typing (the mic button in the board bar) — dictate into the focused thread; text is typed at the cursor when you pause. Toggle with the ~ key. The mic button and the status bar go amber while the microphone is opening and while the speech model loads, and only turn red “Listening…” once the model can actually transcribe — anything you say before the mic is open is lost, while speech during the model load is held and typed as soon as it is ready. In ⚙ Settings → Voice, choose a local model for offline English recognition (Moonshine is bundled; Parakeet and Whisper download on first use), or OpenAI (cloud) with your OpenAI API key. Cloud transcription sends recorded phrases to OpenAI and requires internet access and separate API billing. Stop dictation and let pending phrases finish before switching models. Use the user dictionary to fix words it mishears. Hivemind also learns from your fixes: when you make the same correction twice before sending, it offers to add it to the dictionary. Use 🎓 Train dictionary to practice sentences from your prompt history and review proposed corrections.
          • 
              
        • Every new thread gets a short random name — Leo, Nina, … — shown as its header title. Use it to address the thread in Hivemind commands: “Hivemind, run the tests in Leo” or “Hivemind, tell Leo to fix the login bug”. Double-click the name to rename a thread.
          • 
              
        • Just below the header, the chat view's top bar shows a caption built from the last prompt you send the thread (to the left of the ⋯ menu), so you can see what every thread is working on at a glance. Short replies like yes, no or a menu number don't replace the caption, so answering a prompt keeps the real task on show.
          • 
              
        • Each thread can run a different agent — pick Claude, ChatGPT, Gemini, or Grok from the dropdown in the thread header. One hive can mix them (e.g. three Claude threads and one ChatGPT thread). Switching a running thread restarts it with the new agent and the conversation does not carry over — to move a conversation onto another agent, use ⇄ Hand off to another thread in the chat view's ⋯ menu in the top bar instead. ChatGPT needs OpenAI's Codex CLI (npm install -g @openai/codex), Gemini needs Google's Gemini CLI (npm install -g @google/gemini-cli), and Grok needs the official Grok Build installer from https://x.ai/cli. Launch each CLI once and complete its sign-in flow. If you have the Codex desktop app, its bundled codex is found automatically — no separate install or PATH setup needed. To see which of them are installed and signed in on this machine (and get the install command for one that isn't), run the setup wizard from ⚙ Settings → General → Agent setup. New threads open on the agent set in ⚙ Settings → General → Defaults for new threads → Agent, which the setup wizard also sets to whichever agent you picked.
          • 
              
        • Claude, ChatGPT, and Grok threads have a model dropdown. Hivemind refreshes models from the installed CLIs at startup and when Settings opens; use Refresh agent models after a new release or login. Claude's rolling aliases automatically track their latest family versions. Grok switches live via /model; ChatGPT restarts with a fresh conversation because its model is selected at startup. Gemini currently has no model dropdown. Claude and Grok switch by typing /model into the running thread, so if the thread is showing a menu or a question the switch waits until you've answered it — typing into a menu would otherwise pick an option for you.
          • 
              
        • ChatGPT threads also have an account dropdown, so different threads can run as different ChatGPT logins at the same time. Add accounts in ⚙ Settings → General → ChatGPT accounts — each one gets its own private Codex home, seeded with a copy of your Codex settings but no credentials. To sign a new account in, pick it on a ChatGPT thread and follow Codex's sign-in screen (approve it in a browser signed into that ChatGPT account); an account with no stored login is marked (sign in) and its dropdown is highlighted. The account is read when Codex starts, so switching it restarts the thread with a fresh conversation. Default is whatever codex login put in ~/.codex. Settings also has Sign out (drops the stored login, keeps the account) and Remove (deletes the account's Codex home from this machine; the ChatGPT account itself is untouched).
          • 
              
        • Each Claude thread has a permission mode dropdown in its header — Default, Accept Edits, Auto, Plan, or Bypass ⚠ — so you can see and set the mode without hunting for it in Claude's own display. It's handed to Claude Code as a startup flag (Bypass skips the accept-permissions screen entirely). Since Claude has no command to change mode mid-session, switching a running thread restarts it (resuming the conversation when there is one). If the thread is mid-turn, the switch waits until the turn ends rather than killing the work in flight — the dropdown goes dashed and dimmed while it's pending, and the restart happens as soon as the thread is done (or as soon as you've answered, if it stops to ask you something). The dropdown also follows the thread: if the mode changes inside Claude — you press Shift+Tab in the terminal, or approving a plan moves the thread to auto/manual — the dropdown updates to match, without restarting anything. Bypass turns the dropdown amber as a reminder that permissions are being skipped. The choice is remembered as the default for new threads.
          • 
              
        • When a thread finishes its turn, its whole pane pulses green and the header status shows ✓ done until you click into that thread — so completed work stands out across a busy hive. The hive list's status dot and the maximize tab strip's dots pulse green too. (Threads that need an answer or hit an error still pulse amber/red as before.)
          • 
              
        • Each Claude thread's header shows a ~$ cost estimate: what the conversation so far would have cost at Claude API list prices if it weren't covered by your plan (it's informational — nothing is billed). Hover it for a per-model breakdown of tokens and cost. It counts the whole conversation (including what happened before a restart or resume), resets when /clear starts a new session, and doesn't appear on ChatGPT, Gemini or Grok threads.
          • 
              
        • Change a thread's model from its header. Font size lives in ⚙ Settings → General → Defaults for new threads (the A−/A+ stepper), which resizes every open thread as well as new ones; to resize just the focused thread use Ctrl+=/−/0 or Ctrl+scroll. A narrow thread hides its lower-priority header controls (the permission, model, and agent dropdowns first, then the view toggle's label, then the toggle itself) so the ⛶ maximize and ✕ close buttons always stay reachable — widen or maximize the thread to get the hidden controls back.
          • 
              
        • ⛶ Maximize (or Ctrl+Enter) blows the focused thread up to fill the hive. A tab strip appears across the top listing every other thread — each with a live status dot — so you can see what's hidden behind it and click a tab to jump straight to that thread. Press Ctrl+Enter or ⛶ again to restore the tiled layout.
          • 
            
        
          
        

          
        
            
        Chat view
        
            
          
              
        • Claude and ChatGPT threads open in a chat view: a clean transcript of the conversation — your messages, the agent's replies as formatted markdown, and collapsible tool calls — instead of the raw terminal. The real terminal keeps running underneath, untouched; click the ❯_ Terminal button in the thread header to reveal it (find and scrollback live there) and 💬 Chat to come back. The choice is remembered per thread. Gemini and Grok threads are terminal-only.
          • 
              
        • The bar at the top shows the conversation topic on the left — on Claude threads it's Claude Code's own running summary of the session (once it has one); on ChatGPT threads it's the first message you sent the conversation — and the thread's caption (the last prompt you sent it) left-aligned right after it, with the ⋯ conversation menu and the filter chips on the right.
          • 
              
        • Once a conversation grows past the window and its opening message scrolls out of sight, a PROMPT bar pins itself above the messages showing the prompt the conversation started from — so you can always see what the thread is working on without scrolling back. Click the bar to expand the whole prompt (click again to collapse), or click ↑ on it to jump back to that message in the conversation. It disappears again as soon as the opening message is back on screen, and a conversation you browse from ⋯ › 🕘 Past conversations gets its own.
          • 
              
        • Everything you can do with the conversation itself lives behind the ⋯ chip at the right of that bar: ⇄ Hand off to another thread, 💬 Ask for a second opinion, and 🕘 Past conversations (Claude threads only). Pick one and the same dropdown becomes that action's list — the threads on this hive, or this thread's earlier sessions — with ‹ Back at the top. The chip is also the status light: while a handoff or a second opinion is in flight it says so, and opening it offers the row that stops waiting. It used to be three separate chips, which left no room on the bar for the caption.
          • 
              
        • On Claude threads, the ⋯ menu's 🕘 Past conversations page browses this thread's past conversations. It lists earlier sessions in the project (newest first, titled by their topic or first message); pick one to view it over the live chat. To continue a past conversation, just type in the composer and send — the thread restarts on that conversation (claude --resume) with your message as the next turn. Click Back to live (or the live entry in the menu) to return to the running conversation instead, which keeps updating underneath the whole time.
          • 
              
        • Pick ⇄ Hand off to another thread from the ⋯ menu to pass this conversation on — a different agent, a fresh context window, or just a thread that's free. Pick any other thread on the hive, or New Claude / ChatGPT / Gemini / Grok thread to open one for it. Hivemind asks this thread to write a handoff brief to .hivemind/handoffs/ in the project — the goal, what's already been done and where, the decisions made, open questions, and the next step — and as soon as the brief lands it points the other thread at it and focuses it. The thread doing the handoff is the one that writes the brief because it's the only one that knows what mattered in its own context, so it takes it a turn; the chip reads ⇄ Handing off… meanwhile, and the menu's Stop waiting for the handoff brief row calls it off. Nothing happens to the original thread — the conversation is copied, not moved, so you can hand the same one to several threads. You can also say “Hivemind, hand off to Leo” or “Hivemind, hand this conversation to a new ChatGPT thread”. Handing off works on every agent, including Gemini and Grok threads (use the voice/command form there — they have no chat view). Briefs are git-ignored and swept after a week.
          • 
              
        • Pick 💬 Ask for a second opinion from the ⋯ menu to ask another thread what it thinks and get the answer back here. Pick any other thread on the hive, or New Claude / ChatGPT / Gemini / Grok thread to open one for it. Hivemind asks this thread to write the question and the context behind it to .hivemind/consults/, sends it to the other thread with the outline for an answer, and when that answer lands it delivers it back into this conversation — so the thread you were talking to reads the second opinion and tells you where it agrees and where it doesn’t. Unlike ⇄ Hand off, the conversation never moves: only a question and an answer travel. The chip reads 💬 Writing question… and then 💬 Waiting on ‹thread›… while it runs, and the menu's Stop waiting for the second opinion row calls it off. You can also say “Hivemind, ask Gemini what it thinks about the caching plan”, “Hivemind, get Leo’s opinion on this schema”, or just “Hivemind, ask a new Grok thread” to let this thread pick the question itself. Works on every agent, including Gemini and Grok threads (use the voice/command form there — they have no chat view).
          • 
              
        • A thread can also start a consult on its own: tell the agent itself — in an ordinary message, no “Hivemind” in front — “go ask Codex what it thinks about this”, and it writes the question to .hivemind/consults/ask-‹slug›.md naming who to ask; Hivemind picks it up within a few seconds and runs the same round trip. For that to work the agent has to know the format, which is written for it in .hivemind/consults/README.md — it appears the first time any consult runs on the hive, and each thread knows its own name from the HIVEMIND_THREAD environment variable. To have threads do it unprompted, add a line pointing at that README to your project’s AGENTS.md or CLAUDE.md. Questions and answers are git-ignored and swept after a week.
          • 
              
        • While the thread is working on a turn, a spinning 🌀 swirl appears below the last message; it disappears when the turn finishes.
          • 
              
        • Hover any of the agent's replies to reveal a small ⧉ Copy button at the end of the message — click it to copy that message's raw markdown to the clipboard (it flips to ✓ briefly to confirm). Each code block gets its own ⧉ button in its top-right corner (revealed on hover) that copies just that block's code.
          • 
              
        • When Claude asks you a multiple-choice question, it appears as a question card in the chat — click an option to answer (it presses that option's number in the hidden terminal — plus Enter on the questions Claude Code shows with a preview panel, where the number only moves the selection — and a click only fires while the menu is really still on screen, so a stale card can't press keys into whatever replaced it; on the rare menu with more than 9 options, options past 9 use Interact; multi-select options show a ☑ as you toggle them — click Review ⇥, and Claude Code's confirmation step appears as its own card where Submit answers sends your picks). The thread shows needs you until the question is answered. For a custom answer, click Interact on the card and type in the live controls inside chat. Click Done to close them. Claude Code's plan-approval menu (“Ready to code?” / “Would you like to proceed?”) appears as the same kind of card — with the full plan review embedded right on the card: the plan renders as a collapsible 📋 section above the options, you can highlight any plan text and click ＋ Comment to attach a note (comments appear in a rail under the plan, with ✓ to resolve), and the card's Request changes button (next to the Overall feedback line) picks “No, keep planning” and sends your comments to the thread as the revision request. Click a menu option to approve the plan or keep planning, or click 📋 Open as window to do the same review in a full window instead — both share the same plan and comments. ChatGPT approval prompts (run a command, make edits, grant permissions, network access) appear as the same kind of card too, showing what's being approved with clickable options.
          • 
              
        • Filter chips at the top right (Tools, Thinking, Meta, Subagents) control exactly what the chat shows. Tool calls appear as collapsed one-liners — click one to expand its input and result. Your choices persist per thread and become the default for new threads.
          • 
              
        • The composer at the bottom sends to the thread: Enter sends, Shift+Enter adds a line — multi-line messages arrive as one message. Press ↑ in an empty composer (or on the first line) to recall messages you've sent before, ↓ to come back — editing keeps whatever you land on. Misspelled words get a red squiggle — right-click for suggestions or to add a word to the dictionary — and clear typos are autocorrected the moment you finish a word (Ctrl+Z undoes a fix; Add to dictionary protects a word; turn it off in ⚙ Settings → General → Typing).
          • 
              
        • Click ⏹ Interrupt next to the composer's ➤ send button to stop whatever the thread is running — it sends the same Ctrl+C the terminal would, without you having to open the terminal view first. Handy for cutting off a long-running command or a turn that's gone down the wrong path.
          • 
              
        • Attachments: paste an image (including Win+Shift+S screenshots), drag files onto the chat, or click 📎 to pick files — each shows as a chip above the input (images get a thumbnail preview). Click a chip's ✕ to remove it; when you send, the attached files' paths go along with your message so the agent can read them. On ChatGPT threads, images are handed to Codex as real image input (they appear as [Image #N] in its composer, so the model can actually see them), and other files from outside the project are first copied into .hivemind/attachments/ in the project (the Codex sandbox can only read files inside its workspace); the copies are git-ignored and swept after a week.
          • 
              
        • The composer autocompletes as you type: start a message with / for shared project skills from .agents/skills. Claude threads also suggest Claude commands and legacy project skills. Selecting a shared skill inserts an instruction to read and follow its procedure; add your task details, then send. Shared skills take precedence over legacy skills with the same name. Type @ anywhere to reference a file: every file in the hive is listed, and typing filters the whole project at once — part of a name (@rend) or part of a path (@docs/rend), matched letters shown in bold. Picking one inserts its project path into your message, so the thread reads that file as the context for the prompt. Files your .gitignore hides are left out of the list but still complete once you type their name, and completing a folder steps into it. ↑/↓ pick a suggestion, Tab or Enter accepts it, and Esc dismisses the menu.
          • 
              
        • When the hidden terminal needs something the chat can't show — a permission prompt, an approval menu, or an error — it appears as a card in the chat flow (right where the conversation is), with quick keys (1 and 2 when it's a numbered menu, plus Enter and Esc) and an Interact button showing the live prompt inside chat; like question cards, the keys only fire while the prompt is really still waiting. While a prompt is waiting the composer is locked — a typed message wouldn't reach the terminal (it wants a menu keypress), so answer with the card's keys or use Interact for a custom reply; the composer unlocks the moment the prompt is answered. Ordinary follow-up questions remain answerable directly in the composer. This works on both Claude and ChatGPT threads (ChatGPT approvals appear while the thread still looks busy, and recognized ones render as full question cards instead).
          • 
              
        • If the thread's agent needs you to sign in again — a Claude login that expired, a /login nudge, or the CLI starting up on its login chooser — the chat view says so instead of going quiet: a 🔑 Sign in to continue card appears in the conversation showing exactly what the terminal is asking, with an Interact to sign in button, the thread's header status reads sign in, and you get a notification. The composer stays locked while it lasts, because nothing typed there can reach the thread until it's signed back in — it unlocks by itself once you are.
          • 
              
        • If a message you send gets no response at all and the thread isn't working on it, the message is marked ⚠ no response yet with its own Interact button, so a send that quietly went nowhere (a login screen, a wedged terminal) never just sits there looking delivered.
          • 
              
        • If the agent hits an API error — the chosen model isn't available on your account, a usage limit was hit, the request failed — the full error message appears in the chat as a red error card (it's never hidden by the filter chips), and the thread's status flips to error so you're notified.
          • 
              
        • The chat is read from the thread's local session log — Claude Code's transcript for Claude threads, the Codex CLI's session file for ChatGPT threads. If Hivemind still can't find a Claude transcript a few seconds after you send a message (e.g. a custom startup command that isn't claude), a notice appears — an idle thread you haven't written to yet has no transcript to find, and says nothing; a ChatGPT chat simply fills in from your first message (Codex writes its log when the conversation starts). Click Interact in the notice or chat toolbar to see and operate the live CLI while keeping chat open. This also covers slash-command menus, custom answers, sign-in, and other CLI controls. The ❯_ Terminal / 💬 Chat toggle still switches the whole view.

        Hivemind commands
        
            
        Start a composer message (or a single dictated sentence) with
              “Hivemind” and the rest is a command Hivemind itself carries out instead of
              text sent to Claude — e.g. “Hivemind, open a new thread and fix the failing login test”
              or “Hivemind, increase the font size”. A toast at the bottom of the workspace confirms
              what it did. Anything that starts with “Hivemind” is treated as a command and is
              never sent to the thread; mentioning Hivemind mid-sentence is sent to the thread as normal.
        
            
        You don't have to phrase commands exactly. Hivemind first matches your
              words against the command list below (politeness like “hey, could you please…” is
              ignored automatically), and anything it still doesn't recognize is handed to a quick
              background Claude call that maps your phrasing onto the right command — so
              “this text is way too small” becomes font bigger. That fallback
              takes a few seconds (a “Let me figure out what you mean…” toast shows while it thinks) and
              uses the same Claude Code CLI your threads run on; if even Claude can't map it, the toast
              says so and nothing happens.
        
            
        Prefer a dedicated chat? The 🐝 Chat with Hivemind
              panel (the  chat-bubble button at the bottom of the sidebar, Ctrl+Shift+H,
              or say “Hivemind, chat”) docks into the sidebar — like Source Control or the Explorer —
              and treats every message as a command — no “Hivemind” prefix needed (though it's
              still fine to use one). While the panel is open, the ~ voice hotkey dictates
              into it — stopping the mic sends the command automatically, no ➤ click
              needed. It keeps a transcript of what you asked and what Hivemind answered, and can
              speak the replies aloud — turn that on in
              ⚙ Settings → Voice. Got a command wrong (or misheard)? Hover your
              message and click the ✏ pencil to edit & re-apply it —
              the fixed command runs again, and if you corrected misheard words, Hivemind immediately
              offers to add the fix to the voice dictionary.
        
            
        
            
        “This thread” means the one whose composer you typed into (or the focused
              one when dictating). Dictated commands tolerate misheard wake words — common
              mistranscriptions like “half mine”, “high mind” or “hive mine” at the
              start of an utterance are recognized as “Hivemind” automatically. If yours still isn't caught,
              add a correction in ⚙ Settings → Voice's dictionary (or accept the offer
              Hivemind makes after it sees you fix it yourself twice). To teach the dictionary your
              project's vocabulary up-front, use 🎓 Train dictionary there — read the
              practice sentences aloud and accept the corrections it proposes. Terms it misheard are
              woven into extra sentences later in the session (and lead the next Train again)
              so the fix gets verified in a fresh context. You can also train on one specific prompt:
              hover it in the Prompt History panel and click its 🎤
              button to read that prompt aloud in the same trainer.
        
          
        

          
        
            
        Source Control (Git)
        
            
          
              
        • Push ↑ — stages every change, commits (auto-drafting a message if you left the box empty), then pushes your work up to GitHub. The first time, it connects the repo to GitHub for you. (Ctrl+Enter in the commit message box does the same thing.) If the push is rejected because GitHub has newer commits, Pull first.
          • 
              
        • Pull ↓ — brings down commits made on GitHub (or another machine) and merges them into your branch.
          • 
              
        • ⋯ menu → Revert to GitHub — tucked into the ⋯ overflow menu next to Pull/Push. Discards all local changes and resets the branch to match GitHub. Cannot be undone.
          • 
              
        • Once the repo is connected to a remote, the GitHub icon next to the branch name opens the project's page on GitHub in your browser.
          • 
              
        • The ↓/↑ counters next to the branch name show commits to pull down from / push up to GitHub. Hivemind checks GitHub for new commits in the background while the panel is open (every few minutes); hit ⟳ to check right now.
          • 
              
        • Recent Commits at the bottom of the panel lists the last three commit messages on the current branch — hover one to see its hash, author and when it was made.

        Plan review
        
            
          
              
        • When a Claude thread works in plan mode (the Plan permission mode, or whenever Claude plans on its own), Hivemind detects the plan automatically. While Claude drafts it the thread's header shows a 📋 planning chip; the moment Claude finishes and asks for approval (“Ready to code?” / “Would you like to proceed?”), the review is ready: in the chat view the approval card embeds it right in the conversation (see Chat view above), and in the terminal view the plan pops up as a full document — rendered markdown in an editor-style window that live-updates as the plan is written. If the thread isn't focused, nothing pops up: the header shows a 📋 plan ready chip instead — click it (or the chat card's 📋 Open as window button) to open the review window. To reopen a plan later — say, after it's been approved — use the “Hivemind, show the plan” command in the thread's composer. The auto-popup can be turned off in ⚙ Settings → General → Plan review.
          • 
              
        • Approve · auto-accept and Approve · manual edits answer Claude Code's own approval menu in the hidden terminal — exactly like picking “Yes, auto-accept edits” (or its equivalent in the thread's permission mode, e.g. “Yes, and bypass permissions” — hover the button to see which) or “Yes, manually approve edits” there. The status chip flips to Approved once Claude confirms, and the thread starts implementing. The chat view's approval card offers the same choices as its clickable menu options.
          • 
              
        • Inline feedback: highlight any text in the plan and click ＋ Comment to attach a note to it — like review comments on a document. This works the same in the review window and on the chat card, and both show the same comments. Comments are saved with the project (in .hivemind/plans/, kept out of Git), so they survive restarts.
          • 
              
        • Request changes picks “No, keep planning” in the thread and sends your comments (each with the text it refers to, plus the optional overall-feedback line) as the revision request. Claude revises, the document updates live, and comments you already sent show collapsed with a sent tag. Comments whose text no longer appears in the revised plan are marked (not found in current plan).
          • 
              
        • Plans render as rich markdown — headings, tables, links (which open in your browser), block quotes and task lists. On plans requested via ⟳ (see below) you can tick a checkbox in a - [ ] task list to mark it done — the change is written back to the plan file. Native plan-mode files belong to Claude Code, so their checkboxes are read-only.
          • 
              
        • ChatGPT and other threads (no native plan mode): click ⟳ in the review window to ask the thread to write its plan to .hivemind/plans/ in your project — it renders in the same document view with the same commenting, and Request changes types the comments straight into the thread.
          • 
              
        • ⧉ copies the plan's raw markdown to the clipboard. Esc, ✕, or clicking the backdrop closes the review; the plan stays available on its thread.

        Usage & limits
        
            
        Claude threads and ChatGPT threads bill against different
              subscriptions, so the Usage pill in the toolbar carries one segment per
              agent — Claude 62%  ChatGPT 5% — each showing that agent's most-constrained
              limit right now (green → yellow → red as you approach it). An agent you aren't signed in to
              is left off the pill; hover for the reason.
        
            
        Click the pill for the full picture, agent by agent: every limit window
              with its reset time, then how many tokens each model has used today. Claude
              numbers are live — the same limits as Claude Code's /usage.
              ChatGPT limits are read from what the Codex CLI last recorded, one set per
              signed-in ChatGPT account, so each is stamped with when that account last ran. Any reading
              that isn't current says so underneath, with its age — a refused refresh keeps the last
              numbers rather than blanking them. Figures
              refresh about once a minute; ⟳ in the modal fetches them immediately.
        
          
        

          
        
            
        Building Hivemind
        
            
        The 📦 Build portable copy button in
              Settings → General → Building Hivemind appears only when the active
              hive is pointed at the Hivemind source checkout. It bumps the patch version in
              package.json, runs electron-builder's portable target to produce a single
              self-contained .exe, then publishes it as a GitHub release (tag
              vX.Y.Z, via the gh CLI) and commits & pushes the version bump —
              this is what portable copies in the wild auto-update from. The dist folder opens
              when it finishes. While it runs, the button shows the current stage and a live elapsed timer
              (a build typically takes a few minutes); hover it to see the latest output line. If publishing
              fails the build itself is kept; a failed build restores the old version number.
        
          
        

          
        
            
        Updates (portable build)
        
            
        When you run the portable .exe, Hivemind checks GitHub for a
              newer release on startup. If one exists it asks once; click Update Now and it
              downloads the new version next to the current file, restarts into it, and automatically
              removes the old .exe along with any other older versions sitting in the same
              folder. Boards and settings are preserved. Installed and source
              (npm start) runs never check.
